# ListingForge 第四轮优化方案（v1.3 → v1.4）

> 主题：**交付成熟度** —— 真实用户闭环（物料导出）、核心模块结构化重构、错误信息治理、交付与性能工程化
> 方法：对 v1.3 做结构审计（分支复杂度）、用户旅程走查（物料产出后能去哪）、运维走查（打包/排错/性能数据），共 9 项。

---

## 零、复查发现（审计结论）

| # | 层面 | 问题 | 严重度 |
|---|---|---|---|
| 1 | 用户旅程 | **物料产出后无出口**：8 条 Listing 只能看不能导出，真实卖家需要 CSV 导入平台后台批量上传或存档，产品闭环缺最后一米 | 🟠 高 |
| 2 | 结构 | `rules_engine._eval_rule` 是 **11 分支 if/elif 长链**、`autofix` 9 分支——新增规则类型要改两处长链，与"规则即代码、扩展零成本"叙事不匹配（应：注册一个函数即接入） | 🟠 中 |
| 3 | 安全 | 500 响应直接返回 `{type(exc).__name__}: {exc}`，向客户端泄露内部异常细节（路径/模型名等） | 🟠 中 |
| 4 | 交付工程 | 每次打包 = git archive + 手工 append CI 文件 + 人工核对，易漏；无一键打包脚本 | 🟡 中 |
| 5 | 性能 | 三轮优化只有零散 ad-hoc 计时（"图片 8ms"），**没有可复现的基准数据**，文档中的性能表述无出处 | 🟡 中 |
| 6 | 文档 | README 规则校验截图仍是 v1.2 版（无审计行/矩阵时间戳），与 v1.3 UI 不一致 | 🟡 低 |
| 7 | 测试 | 导出、500 治理、注册表化重构均无用例（重构前必须先有安全网——已有 37 用例可承接） | 🟡 中 |

## 一、优化项与验收标准

### P0 功能闭环

| 项 | 方案 | 验收 |
|---|---|---|
| F1 物料导出 CSV | 新增 `GET /api/products/{id}/export`：全部 Listing 导出 CSV（平台/语言/状态/标题/五点/描述/SEO/规则库版本/校验结论），UTF-8 BOM 保证 Excel 中文不乱码；第 6 步前端加「⬇ 导出全部物料 CSV」 | 下载的 CSV 行数 = 物料数、Excel 打开中文正常；含含逗号/换行转义的单测 |

### P1 结构与安全

| 项 | 方案 | 验收 |
|---|---|---|
| F2 规则引擎注册表化 | `_eval_rule`/`autofix` 的长链重构为**注册表分发**（`@register_check("keyword_hits")` / `@register_fix("truncate")`），新增规则类型 = 新增一个装饰器函数；行为零变化 | 37 个既有用例全绿即回归；`rules_engine.CHECKS/FIXES` 可枚举 |
| F3 500 错误治理 | 全局 handler 对外统一返回"服务器内部错误"通用文案；详情仅入服务端日志；`LISTINGFORGE_DEBUG=1` 时保留详情便于联调 | 客户端看不到异常栈；debug 模式可开；含测试 |

### P1 工程化

| F6 截图更新 | 重拍规则校验页截图（v1.3 审计行 + 矩阵）替换 README 旧图 | 与线上 UI 一致 |

### P2 回归与交付

| 项 | 方案 | 验收 |
|---|---|---|
| F7 回归与交付 | pytest 目标 40+；E2E；UI 冒烟；重录视频（第 6 步含导出按钮）；重打 zip（走 F4 脚本）；交付清单/CHANGELOG v1.4.0 | 全绿 + 三件套一致 |

## 二、不做什么

- 不做 Excel(xlsx) 多 sheet 导出（CSV 已覆盖主流平台后台导入场景，xlsx 引入新依赖）；
- 不做前端框架化/状态库（零构建原则）；
- 不做真实性能优化（本轮先立基准，有数据后下轮按需优化——避免无 profCtrl 的盲目优化）；
- 不启用 CI（仍待 workflow scope 授权，非代码问题）。

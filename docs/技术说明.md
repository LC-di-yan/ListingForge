# ListingForge 技术说明

> AI+跨境黑客松巅峰赛 · 场景一「AI智能上新」· 可运行 Demo 技术文档
> 版本 v1.0.0 · Python 3.10+ / FastAPI / 阿里云百炼（Qwen）

---

## 1. 系统定位与边界

ListingForge 是**端到端 AI 智能上新引擎**：卖家输入基础商品资料（表单 / 参数 / 一张产品照片），系统自动完成「资料结构化 → 多平台多语言 Listing 文案 → 合规白底主图与多尺寸图 → 平台规则校验 → 人工审核 → 多平台批量上架」。

本仓库为**可运行 Demo**：

- 双轨模式：`mock`（本地模拟，离线可跑，开箱即用）/ `qwen`（百炼实时推理），由环境变量 `DASHSCOPE_API_KEY` 自动切换；
- 上架环节使用**模拟适配器**（返回平台商品 ID），适配器签名与官方 API 封装一致，生产替换为真实调用即可；
- 持久层使用 SQLite，生产平替 PostgreSQL（SQL 均为标准写法）。

## 3. 模块设计

### 3.1 文案引擎 `app/generator.py`

| 模块 | 职责 | 关键实现 |
|---|---|---|
| `structure_product` | F1 商品资料结构化，输出 PIM（类目/属性/卖点/关键词/人群） | mock：分类知识库 + 正则启发式（材质/颜色/容量识别，含「蓝牙≠蓝色」消歧）；qwen：`qwen-vl-max` 多模态识别（图片 base64 + 文本），要求只输出 JSON |
| `generate_listing` | F2 多平台多语言文案 | mock：平台化标题模板（亚马逊关键词布局 / 速卖通关键词堆叠 / TikTok 钩子式 / Shopify 品牌式）+ 五点利益点链 + 长描述；qwen：`qwen-plus` 携带平台硬性规则约束生成 |
| `LOCALIZED_LIBRARY` | 多语言本地化重写（非直译） | 按类目 × 西/葡/阿语整段地道文案（标题/五点/描述/SEO 四件套）；未命中类目回退「词库映射 + 本地化框架」改写 |
| 降级策略 | 保证 Demo 永不中断 | qwen 调用失败（网络/限额）自动降级 mock，并在 `pim.source` 中标注原因 |

> 设计原则：**LLM 只做创作、结构由 schema 约束**。所有生成要求模型输出 JSON，服务端再做规则校验兜底。

### 3.2 平台规则引擎 `app/rules_engine.py`（差异化核心）

**规则即代码**：每平台一份 JSON 规则库（`app/rules/`），共 27 条规则，库文件自带 `version` 元字段（当前 v1.3.0）——校验报告的 `ruleset_version` 直接读自规则库并配合 mtime 热加载，改库即改版本，报告可审计。

| 规则类型 | 说明 | 示例 |
|---|---|---|
| `length_max / length_min / length_range` | 字段长度 | 亚马逊标题 ≤200、Shopify 标题 ≤70（SEO）、TikTok ≤90 |
| `banned_words` | 禁用词表 | 亚马逊：Best/#1/Free Shipping…；TikTok：医疗功效词 |
| `no_emoji` | 特殊符号 | 标题不得含 Emoji |
| `list_count / item_length_max` | 列表规范 | 亚马逊五点 =5、每点 ≤240 字符 |
| `attr_required` | 必填属性 | 速卖通类目属性树（材质/颜色/类目） |
| `keyword_hits` | 关键词布局 | 标题需命中 PIM 核心关键词 ≥2（warn 级，生成端保证布局） |
| `image_ratio / image_white_bg / image_min_px` | 主图规范 | 1:1、白底占比 ≥60%、边长 ≥1000px（白底占比由像素统计实测） |

两阶段 API：

- `validate(platform, listing, image, pim)` → 逐条输出 `{pass / fail / warn}` + 实测值 + 是否可自动修复，汇总为报告（含 `ruleset_version` 与 `validated_at` 审计字段）；
- `autofix(...)` → 按 `fix` 钩子自动改写：`strip_banned`（去禁用词）、`truncate`（词边界安全截断）、`adjust_bullets`（五点数量补齐/裁剪）、`pad_description`、`autofill_attr`、`regen_image`（重跑图片管线）等；**修复日志随校验报告持久化到数据库**（`validation.last_autofix`：改了哪些规则、何时改的），前端报告区可见，刷新不丢。

**扩展方式**：新增平台 = 新增 `rules/<platform>.json` +（可选）新增生成 Adapter；规则变更仅改 JSON，无需动代码——这是相对"模板 prompt"方案的工程化护城河。

> 说明：mock 模式下速卖通英文标题会模拟"原始 AI 稿件"混入促销词（Hot Sale / Free Shipping）的常见情形，用于真实演示规则引擎的拦截与自动改写能力；百炼实时模式下规则约束直接写入生成 prompt，违规率显著降低，但校验闸门依然保留。

### 3.3 图片管线 `app/imaging.py`

| 步骤 | 实现 | 说明 |
|---|---|---|
| 背景抠除 | OpenCV `floodFill` 从 8 个边缘种子点连通填充背景 → alpha 通道 + 高斯羽化（抠图前 EXIF 方向转正） | Demo 级抠图；生产替换 `rembg`（U²-Net）或百炼图像编辑 |
| VL 预处理 | `compress_for_vl`：>1.5MB 或长边>1600 的图压缩至长边 1024 再送多模态模型 | 省流量、避开接口上限 |
| 白底主图 | 抠图后等比缩放居中放到纯白 1200×1200 画布（含软投影） | 满足亚马逊 1:1 ≥1000px 纯白背景规范 |
| 多尺寸适配 | 1:1 主图 / 4:5 详情页 / 16:9 横幅 / 9:16 短视频封面，带尺寸角标 | 一图四平台 |
| 场景图 | 渐变背景 + 抠图产品 + 光斑 | 营销素材 |
| 合规自检 | `image_meta` 统计尺寸与**白底像素占比**，供规则引擎实测校验 | 图片规则非"声称合规"，是实测合规 |

生产路线：rembg 抠图 → ComfyUI（Yolain 电商工作流 + productfix 保真节点）改背景不动产品 → Qwen-Image 生成场景图；本模块对外接口 `process_product_image / ensure_compliant_main / image_meta` 保持不变，平滑升级。

### 3.4 编排层 `app/main.py` 与数据模型

REST API（全部可 Swagger 调试）：

| 方法 & 路径 | 功能 |
|---|---|
| `GET /api/meta` | 运行模式、平台/语言清单 |
| `GET /api/samples` · `POST /api/products/sample/{key}` | 内置示例 |
| `POST /api/products`（multipart） | 自定义录入（照片上传：类型/扩展名/大小三重校验，文件名净化防穿越） |
| `GET /api/products` · `GET /api/products/{id}` | 商品列表与详情（含 counts/images，前端会话恢复数据源） |
| `DELETE /api/products/{id}` | 删除商品及物料/任务 |
| `POST /api/products/{id}/structure` | F1 结构化 + F3 图片管线 |
| `POST /api/products/{id}/generate` | F2 按 平台×语言 批量生成并即时校验（4 线程并发；重建式生成保证幂等） |
| `POST /api/products/{id}/validate_all` | 批量校验全部物料（前端合规矩阵数据源） |
| `GET /api/listings/{id}/validate` · `POST …/autofix` | F4 校验 / 自动改写 |
| `PUT /api/listings/{id}` · `POST …/approve|reject` | F5 人审（可改稿） |
| `POST /api/products/{id}/publish` · `GET /api/products/{id}/tasks` | F6 批量上架 + 状态回传 |

数据模型（三表）：`products`（含 PIM JSON）、`listings`（平台×语言×状态机 draft→approved/rejected→published，含校验报告 JSON）、`tasks`（上架任务与平台回执）。全流程留痕可追溯。

### 3.5 平台适配层（生产路线）

Demo 的 `fake_adapter_publish(product, listing)` 与真实适配器同签名：

- Shopify：`shopify_python_api`（POST /admin/api/…/products.json，variants/SEO 直接映射）；
- 亚马逊：`python-amazon-sp-api`（ listingsItems PUT，先沙箱后生产）；
- 速卖通：`aliexpress.open` 产品发布 API（类目属性树由 `attr_required` 规则保证齐全）；
- TikTok Shop：官方 OpenAPI product/create。

失败重试、限流、凭证管理在生产版由 Celery + Redis 任务队列承担。

## 4. 关键设计决策

1. **多步链而非单次生成**：标题→五点→描述分步产出，每步带平台约束，质量与合规双保证；
2. **适配器模式**：平台差异封装在规则库 + 适配器，核心引擎零改动；
3. **AI 出稿 + 人审放行**：状态机强制 `draft → approved → published`，未放行不可上架，贴合真实商用；
4. **可审计性**：PIM、校验报告、修复日志、上架回执全部 JSON 落库；
5. **演示确定性**：mock 模式输出确定，保证评审/视频复现；`samples.py` 内置 3 个示例商品开箱即跑。

## 5.1 质量保障

- **测试**：`pytest` 26 个用例（规则引擎 / 生成器 / 图片管线 / API 集成含幂等与安全回归），`pip install -r requirements-dev.txt && python -m pytest`；
- **UI 冒烟**：`scripts/ui_smoke.py`（Playwright 真浏览器六步流断言，11 项检查）；
- **CI**：`.github/workflows/ci.yml` 于 Python 3.10/3.12 矩阵运行 pytest（启用方式见 README）。

## 5.2 部署安全边界（Demo 有意取舍，生产必读）

| 维度 | Demo 现状 | 生产要求 |
|---|---|---|
| CORS | `allow_origins=["*"]` | 收紧为工作台域名白名单 |

| 密钥 | 环境变量（`.env` 已 gitignore） | KMS / 凭证管理服务 |

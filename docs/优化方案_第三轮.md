# ListingForge 第三轮优化方案（v1.2 → v1.3）

> 主题：**可审计性闭环 + 版本化落地 + 双轨模式安全网**
> 方法：对 v1.2 做"承诺 vs 实现"一致性审计、安全再审、测试盲区扫描，共 12 项，全部执行并验证。

---

## 零、复查发现（审计结论）

| # | 层面 | 问题 | 严重度 |
|---|---|---|---|
| 1 | 一致性 | **规则库"版本化"未落地**：`ruleset_version` 硬编码 `"v1.0.0"`，规则 JSON 无 version 字段——规则内容已改两轮，报告里版本号从没变过，与"规则变更仅需更新规则库版本"的差异化承诺相悖 | 🔴 高 |
| 2 | 一致性 | **自动改写日志未落库**：`fix_log` 只随 HTTP 响应返回，前端刷新/切换商品即丢，"全流程留痕可追溯"缺最后一环 | 🔴 高 |
| 3 | 一致性 | 校验报告无时间戳，无法回答"何时验的" | 🟡 中 |
| 4 | 测试 | **qwen 实时模式零测试**：`structure_product_real` / `generate_listing_real` / JSON 解析 / 异常降级路径完全无覆盖（无 API Key 无法联调，但可用 mock 传输层单测） | 🟠 中 |
| 5 | 测试 | 本地化 fallback 分支（未命中类目库）、非白底图片规则拦截、删除级联，均无用例 | 🟠 中 |
| 6 | 安全 | 上传文件 `upload_{秒级时间戳}_{name}` 同秒同名会互相覆盖 | 🟡 低 |
| 7 | 体验 | 第 3 步重新生成会清除已放行状态（重建式生成的代价），但无任何提示，用户可能误操作 | 🟠 中 |
| 8 | 工程 | FastAPI 元数据 `version="1.1.0"` 落后两个版本；三轮优化无 CHANGELOG，评审难以快速看清演进 | 🟡 中 |
| 9 | 文档 | 技术说明未声明生产部署安全边界（CORS 全开 / 无鉴权是 Demo 有意取舍，需显式声明） | 🟡 低 |

## 一、优化项与验收标准

### P0 一致性与可审计性（本轮核心）

| 项 | 方案 | 验收 |
|---|---|---|
| T1 规则库版本字段落地 | 四平台 JSON 增加 `"version"` 元字段（本轮升 `v1.3.0`），`validate()` 从规则库读取版本而非硬编码 | 修改 JSON 的 version → 报告/前端同步变化（热加载已有）；含测试 |
| T2 修复日志落库 | `autofix` 后将 `fix_log` 与时间合并进 `validation` 报告持久化；前端报告区显示"上次自动改写：N 项 + 规则清单 + 时间" | 改写→刷新页面→日志仍在；UI 冒烟断言 |
| T3 校验时间戳 | 报告增加 `validated_at`（ISO 8601），前端报告摘要行展示 | 报告可见时间 |

### P1 测试盲区（双轨模式安全网）

| 项 | 方案 | 验收 |
|---|---|---|
| T4 qwen 模式单测 | monkeypatch `_dashscope_chat`：JSON 提取、VL 图片消息构造、`structure/generate` 真实路径、**异常自动降级 mock 且 source 标注原因** | 新增 ≥5 用例 |
| T5 补盲用例 | 本地化 fallback（未知类目走词库映射+框架改写）、非白底原图被图片规则拦截、删除商品级联清空 listings/tasks | 新增 ≥3 用例 |

### P1 体验与工程

| 项 | 方案 | 验收 |
|---|---|---|
| T6 重新生成确认 | 存在 approved/published 物料时，点击生成弹 confirm 提示将清除放行状态 | 前端逻辑 + 冒烟覆盖 |
| T7 上传唯一名 | 文件名时间戳 → `uuid4().hex[:8]`，消除同秒覆盖 | 代码审查 |
| T8 版本治理 | FastAPI version 1.3.0；新增 `CHANGELOG.md`（v1.0→v1.3 演进一览） | 文件齐备 |
| T9 安全边界声明 | 技术说明新增"部署安全边界"小节（CORS/鉴权为 Demo 取舍，生产清单） | 文档一致 |

### P2 交付

| 项 | 方案 | 验收 |
|---|---|---|
| T10 文档同步 | 技术说明（版本化真实现、审计字段）、README 测试数更新 | 一致 |
| T11 回归与交付 | pytest 目标 33+；E2E；UI 冒烟；重录视频（报告区新增审计行）；重打 zip；交付清单 v1.3.0 | 全绿 + 三件套一致 |

## 二、不做什么

- 不引入规则引擎 DSL/表达式引擎（当前 8 种规则类型够用，避免过度设计）；
- 不做前端框架化、不做国际化框架（保持零构建）；
- 不真实调用百炼（无 Key；以 mock 传输层单测保证代码路径正确，联调步骤写入文档）。

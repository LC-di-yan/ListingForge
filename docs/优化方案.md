# ListingForge 全面优化方案（v1.0 → v1.1）

> 目标：在不破坏"开箱即跑、离线可演示"两大原则的前提下，从**产品体验、文案质量、工程质量、性能、测试与交付**五个层面完成一轮系统化优化，并全部执行落地、验证通过。

---

## 零、问题盘点（现状审计结论）

| # | 层面 | 问题 | 严重度 |
|---|---|---|---|
| 1 | 工程 | `requirements.txt` 缺 `opencv-python`/`numpy`，本机靠全局包侥幸通过；评审新机器执行图片管线会 `ModuleNotFoundError` | 🔴 阻断 |
| 2 | 产品 | **刷新页面状态全丢**：state 不从 DB 恢复，也不能切换历史商品，与"全流程留痕可追溯"承诺不符 | 🔴 高 |
| 3 | 性能 | 生成接口串行生成 N 条 Listing；qwen 实时模式下 8 条 ≈ 8 次串行 LLM 调用（40s+） | 🟠 中 |
| 4 | 性能 | 图片管线每次结构化都重跑（无幂等缓存）；listings/tasks 表无索引 | 🟡 低 |
| 5 | 文案 | `_short` 按字符截断产生 "Vacuum-insulated, keeps" 类残句；Amazon/TikTok 标题模板生硬 | 🟠 中 |
| 6 | 工程 | `@app.on_event("startup")` 已废弃；上传无类型/大小校验；无日志；规则库改动需重启 | 🟡 中 |
| 7 | 质量 | **零测试**；无 CI；重构无安全网 | 🟠 中 |
| 8 | 交付 | README 无截图（GitHub 门面弱）；宣称 MIT 却无 LICENSE 文件；无 .env 示例 | 🟡 中 |
| 9 | 产品 | 校验页一次只能看一条报告，缺少"全部物料合规状态"总览，"批量"感知弱 | 🟡 中 |
| 10 | 前端 | 图片 web 路径靠 `toWeb()` 字符串 hack，后端应直接返回可用的 web 路径 | 🟡 低 |

## 一、优化项与验收标准

### A. 产品体验（P0）

| 项 | 方案 | 验收 |
|---|---|---|
| A1 会话恢复 | 刷新后自动从 DB 恢复最近商品及其 listings/tasks/图片，定位到对应步骤 | 刷新页面 → 自动回到上次进度 |
| A2 多商品切换 | 侧栏新增"历史商品"列表，点击即切换全量状态 | 创建 ≥2 商品后可来回切换 |
| A3 图片路径规范化 | 后端统一返回 `/data/...` web 路径（`product`/`structure` 接口），删除前端 `toWeb` hack | 页面所有图片正常，接口返回即用 |
| A4 校验汇总矩阵 | 校验页新增"全部物料合规总览"表 + 一键批量校验，行点击即选中该 Listing | 8 条物料一屏看清通过/违规 |
| A5 门面 | 顶栏加 GitHub 仓库链接 | 点击可跳转 |

### B. 文案质量（P0）

| 项 | 方案 | 验收 |
|---|---|---|
| B1 `_short` 语义截断 | 先取逗号前主短语，再按词边界截断（`Vacuum-insulated: keeps...` → `Vacuum-insulated`） | 标题/描述无残句 |
| B2 标题模板打磨 | Amazon/Shopify/TikTok 模板用干净的 f1/f2 短语；速卖通保留关键词堆叠风格 | 四平台标题可读、无怪异连接 |

### C. 性能（P0/P1）

| 项 | 方案 | 验收 |
|---|---|---|
| C1 生成并发化 | `generate` 用 ThreadPoolExecutor(max_workers=4) 并发生成（mock 无感，qwen 模式 8 条提速 ~4x） | 接口耗时下降；DashScope 限流安全 |
| C2 图片管线幂等 | 产物齐全且新于源图时跳过重生成 | 二次 structure 秒回 |
| C3 数据库索引 | listings/tasks 表加 product_id 索引，SQLite 开 WAL | 查询走索引（EXPLAIN 验证） |

### D. 工程质量（P0/P1）

| 项 | 方案 | 验收 |
|---|---|---|
| D1 依赖修复 | requirements 补 `opencv-python`、`numpy` | 全新 venv 装依赖后全流程可跑 |
| D2 API 现代化 | lifespan 替换 on_event；启动打印体验信息 | 无 DeprecationWarning |
| D3 上传校验 | 仅 PNG/JPG/WebP、≤8MB，违规返回 400 | 非法上传被拒 |
| D4 日志 | logging 配置 + 关键链路（结构化/生成/上架）耗时打点 | 控制台可见结构化日志 |
| D5 规则热加载 | 规则库按 mtime 缓存失效，改 JSON 即生效无需重启 | 修改规则文件后直接生效 |
| D6 测试套件 | pytest：规则引擎单测、生成器单测、图片管线测试、API 全流程集成测试（TestClient + 临时 DB） | `pytest` 全绿（≥25 用例） |
| D7 CI | GitHub Actions：push/PR 自动跑 pytest（3.10/3.12 矩阵） | 仓库 Actions 绿勾 |

### E. 交付与文档（P1）

| 项 | 方案 | 验收 |
|---|---|---|
| E1 README 截图 | 重拍新 UI 截图嵌入 README（结构化页/规则校验页/上架页） | GitHub 首页有图 |
| E2 LICENSE + .env.example | MIT LICENSE 文件、`.env.example`（DASHSCOPE_API_KEY 说明） | 文件齐备 |
| E3 视频与提交包同步 | UI 变化后重录演示视频、重打 zip、更新交付清单 | 三者与代码一致 |

## 二、执行顺序

1. B 层（后端文案）→ 2. D1-D5（后端工程化 + 性能）→ 3. A 层（后端图片路径 + 前端体验）→ 4. D6-D7（测试与 CI，跑绿）→ 5. E 层（文档/视频/打包）→ 6. 全量回归（E2E + 全新环境验收）→ 7. 提交推送

## 三、不做什么（范围控制）

- 不引入前端框架/构建链（违背零依赖快速体验原则）；
- 不接真实平台 API（保持模拟适配器，属生产路线而非本轮优化）;
- 不改数据库引擎（SQLite 满足 Demo，生产平替路径已在技术说明中声明）；
- 不做多用户/鉴权（Demo 单机场景）。
